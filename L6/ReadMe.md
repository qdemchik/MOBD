### Задание 1. Добавление и заполнение столбца JSONB
**Текст запроса:**
```sql
ALTER TABLE products ADD COLUMN IF NOT EXISTS attributes JSONB;
UPDATE products SET attributes = CASE 
    WHEN id % 3 = 0 THEN '{"color": "black", "weight": 150, "material": "plastic"}'::jsonb
    WHEN id % 3 = 1 THEN '{"color": "white", "pages": 300, "author": "Unknown"}'::jsonb
    ELSE '{"color": "red", "size": "XL", "brand": "NoName"}'::jsonb
END;
```
**Назначение:** Перевести хранение слабоструктурированных атрибутов из гипотетических отдельных таблиц в единый бинарный JSON-документ, что ускоряет доступ и позволяет индексировать содержимое.

**Назначение:** Продемонстрировать работу операторов `->>` (возврат значения как текст) и `@>` (проверка вхождения JSON-фрагмента).

### Задание 4. Добавление B-tree индексов и сравнение планов
**Текст запроса:**
```sql

SELECT c.name, SUM(oi.quantity * oi.price_at_purchase) AS total_revenue
FROM categories c
JOIN product_categories pc ON c.id = pc.category_id
JOIN products p ON pc.product_id = p.id

ORDER BY total_revenue DESC;
```

**Назначение:** Ускорить операции соединения (JOIN). После создания индексов планировщик заменяет `Seq Scan` на `Index Scan` или `Bitmap Heap Scan`, что значительно сокращает время выполнения.

### Задание 5. Создание GIN-индекса для JSONB
**Текст запроса:**
```sql
CREATE INDEX idx_products_attrs ON products USING GIN(attributes);
EXPLAIN ANALYZE
SELECT name FROM products 
WHERE attributes @> '{"color": "black"}';
```
**Назначение:** Показать, что обычный B-tree не умеет работать с оператором вхождения `@>`. GIN-индекс позволяет планировщику использовать `Bitmap Index Scan` вместо полного перебора таблицы.

### Задание 7. Обоснование выбранных индексов
На основе планов выполнения были добавлены:
1. **B-tree индексы** по столбцам `shop_id`, `product_id` в таблице `order_items`. Они критичны для ускорения `JOIN` операций, которые используются во всех аналитических запросах маркетплейса.
2. **GIN-индекс** по столбцу `attributes`. Он необходим исключительно для поддержки операторов работы с JSONB (`@>`, `?`), для которых стандартный B-tree неприменим.

## 3. Принятые проектные решения

- **Выбор типа JSONB вместо JSON:** JSONB хранит данные в разобранном двоичном виде. Он занимает чуть больше места при вставке, но обеспечивает быстрый доступ к полям, удаляет дубли ключей и, главное, поддерживает индексирование, что критично для фильтрации характеристик.
- **Осознанное ограничение количества индексов:** Индексы не были созданы на все столбцы подряд (например, на `description` или `name`), так как это замедлило бы массовую вставку данных и заняло бы лишнее место на диске без существенного выигрыша в скорости для текущих запросов.
- **Использование GIN для JSONB:** Поскольку задача требовала фильтрации по вхождению фрагмента (`@>`), был выбран тип индекса GIN (Generalized Inverted Index), который эффективно поддерживает проверку вхождения для составных значений.

## 4. Ответы на контрольные вопросы

1. **Что такое тип JSONB, чем он отличается от JSON и для каких данных подходит?**  
   `JSON` хранит текст как есть, а `JSONB` — в разобранном двоичном виде. `JSONB` предпочтителен, так как обеспечивает быстрый доступ, удаляет пробелы и дубли ключей и поддерживает индексирование. Подходит для слабоструктурированных или изменчивых атрибутов (например, характеристик товаров).
2. **Какими операторами извлекают поля из JSONB и проверяют вхождение фрагмента?**  
   `->` возвращает значение как JSON, `->>` — как текст. `#>` и `#>>` извлекают по пути. Оператор `@>` проверяет вхождение фрагмента, а `?` — наличие ключа.
3. **Что такое индекс и как он ускоряет выборку данных?**  
   Индекс — вспомогательная структура, позволяющая быстро находить строки по значению столбца без необходимости просматривать всю таблицу целиком (избегая Seq Scan).
4. **Чем последовательное сканирование (Seq Scan) отличается от индексного (Index Scan)?**  
   `Seq Scan` читает все строки таблицы подряд (оправдано при выборке большой доли строк). `Index Scan` находит строки через индекс и эффективен при выборке небольшой доли строк.
5. **Какой тип индекса используется по умолчанию и для каких условий он эффективен?**  
   По умолчанию используется B-tree. Он эффективен для сравнений на равенство, диапазонных условий (`>`, `<`, `BETWEEN`) и поддерживает сортировку.
6. **Что показывает команда EXPLAIN и чем от неё отличается EXPLAIN ANALYZE?**  
   `EXPLAIN` показывает план выполнения с оценочной стоимостью без запуска запроса. `EXPLAIN ANALYZE` реально выполняет запрос и показывает фактическое время и число обработанных строк.
7. **Как по плану выполнения определить, используется ли индекс?**  
   Если в плане появляется узел `Index Scan`, `Index Only Scan` или `Bitmap Index Scan` вместо `Seq Scan` по нужному столбцу, значит, индекс задействован.
8. **Почему индексы не следует создавать на все столбцы подряд? Какова их цена?**  
   Индексы занимают место на диске и замедляют операции вставки, обновления и удаления, так как их приходится постоянно поддерживать в актуальном состоянии.
9. **Что такое GIN-индекс и в каких случаях он применяется?**  
   GIN (обобщённый инвертированный индекс) применяется для индексирования JSONB, массивов и полнотекстового поиска. Он эффективно поддерживает проверку вхождения (`@>`), для которой B-tree не подходит.
10. **Как индексы влияют на операции вставки и обновления данных?**  
    Они замедляют `INSERT` и `UPDATE`, потому что при изменении данных в таблице СУБД вынуждена вносить соответствующие изменения и во все связанные индексы.
